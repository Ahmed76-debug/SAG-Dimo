# Smart Activity Group / مجموعة الأنشطه الذكيه — النسخ التجريبية الكاملة

هذا المجلد **مستقل تماماً** عن `مشروعات ويب`. كل ما تحتاجه التجربة والنشر موجود هنا.
لم يتم تعديل أي ملف من ملفات المصدر الأصلية.

## ما الذي تم بناؤه؟

- **12 نسخة ديمو** لكل مشروعات الويب، داخل `projects/` (ملفات مصدر فقط — بدون بيانات عملاء أو مفاتيح ترخيص أو `node_modules` ثقيلة).
- **بوابة عرض** عربية على `http://localhost:8000/` تعرض كل الديمو بحالة الاتصال.
- **خادم ديمو ذكي** (`demo-server.mjs`) يقوم بـ:
  - تشغيل كل مشروع بخادمه الحقيقي → **CRUD كامل كما في النسخة الأصلية** (إنشاء / قراءة / تعديل / حذف).
  - عزل بيانات كل مشروع في `runtime-data/<id>/` وتوليدها من جديد عند كل بداية.
  - حقن شريط «نسخة تجريبية» في كل صفحة + زر **دخول تجريبي** (يعبّئ بيانات الدخول تلقائياً) + زر **إعادة ضبط البيانات**.
  - توفير مسار واحد للنشر: `https://your-domain.com/<id>/` بدل 12 منفذاً.
- **Express مشترك** في `node_modules/` (نسخة 5)، لتعمل بدون إنترنت.
- **Dockerfile / docker-compose.yml** للنشر.

## التشغيل محلياً (أسهل طريقة)

1. افتح مجلد `نسخه ديمو ويب`.
2. انقر مرتين على **`start-demo.bat`** (أو `./start-demo.sh` على Linux/Mac).
3. افتح المتصفح على `http://localhost:8000/`.
4. اختر أي مشروع واضغط «دخول تجريبي» من الشريط أعلى الصفحة.

> ملف `start-demo.bat` يستخدم Node الموجود في `..\مشروعات ويب\desktop-shell\runtime\node.exe` تلقائياً،
> أو أي Node 22+ مثبت على الجهاز. لا حاجة لتثبيت شيء.

## تشغيل يدوي

```bat
node setup-demo.mjs      :: إعادة نسخ المصادر (فقط عند التحديث)
node demo-server.mjs     :: التشغيل
```
ثم افتح `http://localhost:8000/`.

## إعادة التوليد والضبط

- عند كل إعادة تشغيل للخادم: كل بيانات الديمو تُحذف ويتم بذر بيانات تجريبية جديدة تلقائياً.
- زر **«إعادة ضبط البيانات»** داخل أي ديمو يفعل نفس الشيء فوراً دون إيقاف الخادم.
- يمكن też استدعاء：`POST /__demo/reset?id=auto-car`.
- فحص الحالة: `GET /__demo/health`.

## ملاحظات تقنية

- كل مشروع يعمل بـ `node:sqlite` المدمج → يحتاج **Node 22.5+** (النسخة الموجودة لديك 26.11.1).
- البوابة تعمل على منفذ واحد (`8000`) وتوجّه `/<id>/` إلى المشروع المناسب، لذلك تنشر خدمة واحدة فقط.
- مع path routing يتم تعديل طلبات الواجهة (`fetch`/`XHR`/الروابط) تلقائياً لتعمل تحت `/<id>/`.
- لإتاحة المنافذ المباشرة محلياً (مثل 4500): شغّل مع `set DEMO_DIRECT_PORTS=1` قبل الأمر.
- إذا أردت تقليل الاستهلاك على استضافة محدودة، احذف مشروعاً أو أكثر من `demo-projects.json` قبل النشر.

## إصلاحات مطبّقة في نسخ الديمو فقط

- `auto-car/lib/crud.js`: تفادي كتابة `updated_at`/`created_at` في الجداول التي لا تحتويهما (كان يسبب خطأ 500 عند التعديل).
- إعادة كتابة روابط الأصول وحقن `basename` الخاص بـ React Router حتى تعمل صفحات Vite تحت `/<id>/` بدل 404.
- زر «دخول تجريبي» ينتظر ظهور نموذج الدخول ويملأ الحقول بطريقة متوافقة مع React، ويعمل حتى لو كان الدخول في صفحة منفصلة.
- تحريك العناصر المثبّتة (مثل الشريط الجانبي والشعار) تلقائياً أسفل شريط الديمو حتى لا تُغطّى.
- هذه المشاكل كانت موجودة في المصدر الأصلي أيضاً، وقد تم إصلاحها في المصدر كمان بعد موافقتك.

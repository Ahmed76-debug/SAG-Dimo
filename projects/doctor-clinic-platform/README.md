# منصة طبيب — نظام إدارة العيادة المتكامل

نظام عربي كامل (RTL) لإدارة عيادة طبية: ملف تعريفي عام للطبيب، حجز إلكتروني مع تحقق من الدفع، إدارة المرضى والمواعيد، سجل طبي إلكتروني، وصفات، فواتير، أرشيف، تقارير، مستخدمون وصلاحيات، وإعدادات — مع وضع ليلي وتصميم متجاوب بالكامل.

## البنية الحالية

التطبيق واجهة React/Vite تعمل فوق **خادم SQL مُدار** محلي:

| الطبقة | التقنية |
| --- | --- |
| الواجهة | React 19 + TypeScript + Vite + Tailwind |
| الخادم | Node.js + Express 5 |
| قاعدة البيانات | SQLite عبر `node:sqlite` (`DatabaseSync`) |
| المصادقة | HMAC Token (صلاحية 7 أيام) + PBKDF2-SHA256 لكلمات المرور |
| ملف البيانات | `data/tabib.db` |

كل عمليات القراءة والكتابة تمر عبر REST API، ولا تعتمد الواجهة على `localStorage` أو IndexedDB لتخزين بيانات العيادة.

## التشغيل السريع

من جذر المشروع:

```bat
start-web.bat
```

أو من داخل مجلد المشروع:

```bat
start-web.bat
```

يفتح الخادم تلقائيًا على:

```
http://127.0.0.1:5191
```

مع فتح المتصفح الافتراضي مباشرة. لا حاجة إلى تشغيل خطوات يدوية.

### التشغيل اليدوي

```bash
npm install

# تطوير: API على 5191 + Vite على 5190
npm run dev

# إنتاج: بناء الواجهة ثم تشغيل الخادم على 5191
npm run build
npm run server
```

## الصفحات العامة

- `/doctor` — الملف التعريفي للطبيب.
- `/book` — حجز موعد في 3 خطوات (خدمة وموعد → بيانات → دفع وتأكيد).
- `/login` — دخول فريق العيادة.

الصفحتان `/doctor` و`/book` لا تحتاجان تسجيل دخول، وتستخدمان:

- `GET /api/public/content`
- `GET /api/public/slots`
- `POST /api/public/bookings`

## المزايا

- **بيانات دائمة على الخادم:** تُحفظ كل التعديلات في SQLite، مع مزامنة تلقائية بعد كل تغيير.
- **حجز إلكتروني عام:** يرى الزائر الأوقات المحجوزة فقط (بدون أسماء المرضى)، مع حد 5 طلبات يوميًا لنفس الرقم.
- **محرك تذكيرات واتساب:** يقرأ مواعيد الغد، الحجوزات غير المدفوعة، الفواتير المتأخرة، والمتابعات، ويرسل قوالب عربية معتمدة ويسجّل حالة كل رسالة. يبدأ في **وضع معاينة آمن** حتى تُعتمد القوالب.
- **تذكيرات يدوية:** روابط `wa.me` عربية جاهزة، نسخ فوري، تصدير CSV، وسجل تواصل قابل للتراجع.
- سجل طبي: زيارات، تشخيص، علامات حيوية، حساسية وأمراض مزمنة، مرفقات.
- وصفات طبية ببنود جرعات ومدة، ومستندات جاهزة للطباعة.
- فواتير ببنود وخصم وضريبة، دفع جزئي/كامل، **زر طباعة منفصل** و**زر تصدير PDF** مستقل (html2canvas + jsPDF).
- مواعيد: تقويم أسبوعي، أوقات متاحة، حالات (منتظر، جارٍ، مكتمل، ملغي).
- أرشيف طبي بفلاتر، وتقارير مالية وتشغيلية.
- صلاحيات حسب الدور (طبيب، مدير، استقبال، تمريض، حسابات) + صلاحيات استثنائية لكل مستخدم.
- وضع ليلي/نهاري، وإعادة ضبط البيانات التجريبية من صفحة الإعدادات.
- نسخ احتياطي JSON مع اختيار مجلد الحفظ في المتصفحات الداعمة، واستعادة من ملف أو من مجلد (أحدث نسخة) بعد معاينة وتأكيد.
- متجاوب بالكامل حتى عرض 390px بدون تمرير أفقي.

## واجهات API الرئيسية

| المسار | الوصف |
| --- | --- |
| `POST /api/auth/login` | تسجيل الدخول وإصدار Token |
| `GET /api/auth/me` | بيانات المستخدم الحالي |
| `GET /api/state` | جلب الحالة الكاملة (يتطلب Token) |
| `PUT /api/state` | حفظ الحالة الكاملة (يتطلب Token) |
| `GET /api/stats` | إحصاءات الجداول والصفوف |
| `GET /api/public/content` | محتوى الصفحة العامة |
| `GET /api/public/slots` | الأوقات المتاحة للحجز |
| `POST /api/public/bookings` | إنشاء طلب حجز عام |

## البيانات التجريبية

عند أول تشغيل يُنشئ الخادم قاعدة البيانات ويضيف بيانات العرض تلقائيًا:

- 22 مريضًا
- 49 موعدًا
- 16 زيارة
- 12 وصفة
- 18 فاتورة
- 6 طلبات حجز
- 12 سجل أرشيف
- 7 مستخدمين

لإعادة توليد لقطة البيانات التجريبية من كود الواجهة:

```bash
npm run seed:demo
```

ولإعادة ضبط قاعدة البيانات بالكامل: أوقف الخادم، احذف `data/tabib.db*`، ثم شغّله من جديد — سيُعاد إنشاء البيانات التجريبية تلقائيًا.

## النسخ الاحتياطي

- من داخل التطبيق: الإعدادات → نسخ احتياطي / استعادة (JSON).
- على مستوى الخادم: انسخ ملف `data/tabib.db` (مع ملفات `-wal` و`-shm` إن وجدت) بعد إيقاف الخادم.

## الوضع السحابي (اختياري)

ما زال الكود يدعم Supabase عند ضبط:

```env
VITE_SUPABASE_URL=...
VITE_SUPABASE_ANON_KEY=...
```

لكن **الوضع الافتراضي والموصى به محليًا** هو خادم SQL المُدار أعلاه. راجع `docs/CLOUD_SETUP.md` إن أردت تفعيل السحابة.

## القيود الحالية

- عيادة واحدة (single-tenant)، وليست منصة SaaS متعددة العيادات.
- المزامنة بين الأجهزة تحتاج تشغيل الخادم على جهاز مركزي أو نشر السحابة.
- الإرسال التلقائي للواتساب يحتاج قوالب Meta معتمدة وسياسة رسائل صحيحة.
- تصدير PDF يعتمد على المتصفح وقد يختلف تنسيق الخطوط بين الأنظمة.

## 1. نظرة عامة على المشروع

**منصة طبيب** تطبيق SPA أحادي الصفحة مبني بـ `Vite + React + TypeScript`. يدعم وضعين:

- **محلي**: يعمل بالكامل بدون مفاتيح Supabase باستخدام `localStorage`
- **سحابي**: متصل بـ `Supabase` مع `Auth`, `Postgres`, `RLS`, `Storage`, `Edge Functions`

## 2. التقنيات والمكتبات المستخدمة

| التقنية / المكتبة | الغرض | ملاحظات |
|---|---|---|
| **Vite 5** | بناء سريع + HMR | للتطوير والإنتاج |
| **React 18** | واجهة المستخدم | Hooks + Context API |
| **TypeScript 5** | كتابة آمنة | فحص الأنواع صارم |
| **React Router DOM 6** | التوجيه | SPA |
| **@supabase/supabase-js 2** | طبقة السحابة | Auth، PostgREST، Functions، Storage |
| **html2canvas + jspdf** | طباعة وتصدير PDF | للفواتير والوصفات |
| **lucide-react** | أيقونات | متناسقة وحديثة |

## 5. حالة التطبيق (AppProvider / Context)

ملف `src/state/AppProvider.tsx` هو القلب:

- **قاعدة البيانات**: `db`, `setDb`, `updateSettings`, `save`, `remove`
- **المصادقة والصلاحيات**: `session`, `login`, `loginAs`, `logout`, `hasPerm`
- **المظهر**: `theme`, `setTheme`, `toggleTheme`
- **السحابة**: `cloud`, `syncNow`, `pullCloud`, `pushDemoToCloud`
- **النسخ الاحتياطي**: `restoreBackup`
- **العمليات**: `changePassword`, `runDispatch`, `getBookedSlots`

يستخدم `diffDB`, `pushChange`, `fetchAllData` للتزامن مع Supabase.

## 6. طبقة البيانات المحلية والسحابة

### `src/lib/cloud.ts`
- **تحويل البيانات**: `toRow` / `fromRow` بين `camelCase` و`snake_case`
- **جدول التحويل**: `TABLES`, `DATE_COLUMNS`, `NULLABLE_COLUMNS`
- **المزامنة**: `diffDB`, `pushChange`, `pushSingletons`, `fetchAllData`
- **استعادة سحابية**: `restoreCloudBackup` (يبني payload بدون `users` ويرسل لــ `restore-backup`)
- **أدوات مساعدة**: `getSupabase`, `cloudEnabled`, معالجة الأخطاء

### `src/lib/backup.ts`
- **بناء النسخة**: `buildBackup(db)` يصدر envelope `{app:"tabib-clinic", version:1, createdAt, data}`
- **القراءة والتحقق**: `readBackupFile` ← `parseBackupText`
- **التحقق**: فحص بنية، المراجع بين الجداول، التكرار، القيم الفريدة (`code`, `ref`, `number`)
- **الحفظ**: `saveBackupFile` (File System Access API ← `showSaveFilePicker` ← تنزيل)
- **اختيار ملف**: `pickBackupFile` (Open Picker ← input مخفي)
- **اختيار مجلد**: `pickBackupFromFolder` (Directory Picker + البحث عن أحدث `tabib-backup-*.json`)
- **الدعم**: يقبل النسخ القديمة (raw DB)، ويرفض إصدارات أحدث

## 7. المكونات UI
تقع في `src/components/ui/` مع مكونات مشتركة: `Button`, `Card`, `Modal`, `ConfirmDialog`, `Field`, `PageHead`, `Tabs`, `Badge` وغيرها. التصميم يدعم RTL والوضع الليلي.

## 8. النسخ الاحتياطي والاستعادة تقنيًا

### محليًا
1. اختيار ملف أو مجلد → قراءة → `parseBackupText` يتحقق ويُطابق ويُدمج مع `defaultSettings`/`defaultProfile`
2. عرض تأكيد بعدد السجلات
3. `restoreBackup(next)` يستبدل `db` مع الاحتفاظ بالمستخدم الحالي، يحفظ في `localStorage`
4. تحديث الفورم وإعادة التحميل

### سحابيًا
1. `Settings` يبني `payload` بجميع المجموعات ماعدا `users` + `settings` + `profile`
2. `restoreCloudBackup` يستدعي `supabase.functions.invoke('restore-backup', { body: { payload } })`
3. **Edge Function** `restore-backup`: يتحقق من المصادقة + صلاحية `settings.edit`، يرفض استدعاء Cron، يتحقق من البنية
4. يستدعي `supabase.rpc('restore_clinic_backup', { payload })` بصلاحية `service_role`
5. **SQL Function**: يتحقق من `auth.role() = service_role`، يفحص المصفوفات، **ينفذ `TRUNCATE ... CASCADE`** داخل معاملة، يعيد إدخال البيانات بالترتيب الصحيح مع `coalesce` للقيم الافتراضية، يحدّث `settings`/`doctor_profile` مع `updated_by = null`، يسجّل عملية الاستعادة في `audit_log`
6. **AppProvider** يحافظ على `users` الحالي، يحدث الحالة، يحدد `syncedRef` لمنع إعادة المزامنة

## 9. Supabase: مخطط البيانات، RLS، Edge Functions

### ملفات الترحيل بالترتيب
| الملف | الغرض |
|---|---|
| `supabase/migrations/0001_init.sql` | إنشاء الجداول، RLS، `has_permission`, `role_permissions`, triggers، `guard_public_booking`، `booked_slots_range`، دوال مساعدة |
| `supabase/migrations/0002_storage.sql` | بكتات `medical-files` و`payment-proofs` خاصة، وسياسات Storage |
| `supabase/migrations/0003_restore_backup.sql` | دالة `restore_clinic_backup` المعاملاتية للاستعادة الآمنة |

### Edge Functions
| الدالة | الغرض | التحقق |
|---|---|---|
| `admin-users` | إنشاء/تحديث المستخدمين بأمان | JWT + صلاحية مناسبة / service |
| `reminders-dispatch` | محرك التذكيرات اليومي | JWT أو `x-cron-secret` |
| `whatsapp-webhook` | استقبال أحداث WhatsApp | توقيع Meta HMAC |
| `restore-backup` | استعادة النسخة الاحتياطية السحابية | JWT + صلاحية `settings.edit` (يرفض Cron) |

تم تحديث `supabase/config.toml` لتضمين `restore-backup` بـ `verify_jwt = false`.

## 12. التطوير المحلي

1. `npm install`
2. للعمل محليًا فقط: لا تضف متغيرات Supabase ويعمل تلقائياً
3. للعمل سحابيًا محليًا: أضف `VITE_SUPABASE_URL` و`VITE_SUPABASE_ANON_KEY` في `.env.local`
4. `npm run dev`

## 14. الأمان وأفضل الممارسات

- **RLS**: مفعّل على جميع الجداول السريرية
- **المفاتيح**: `anon` فقط للمتصفح، `service_role` حصرًا للخادم/Edge Functions
- **Auth**: يديره Supabase Auth، لا تُخزّن كلمات المرور في جداول التطبيق
- **Storage**: بكتات `medical-files` و`payment-proofs` خاصة
- **التدقيق**: `audit_log` لتسجيل التعديلات
- **حجز عام آمن**: الحد اليومي + `guard_public_booking`
- **الاستعادة**: معاملاتية، إبقاء حسابات Auth، فحص صلاحيات
- **النسخ الاحتياطي**: احتفظ بنسخ منتظمة، فعّل **PITR** في Supabase للإنتاج

## 15. استكشاف الأخطاء وإصلاحها

| المشكلة | السبب المحتمل | الحل |
|---|---|---|
| فشل الاستعادة السحابية | لم يُطبق `0003` أو لم تُنشر دالة `restore-backup` | طبّق الترحيلات بالترتيب وانشر الدالة |
| زر "اختيار مجلد" غير ظاهر | متصفح غير مدعوم لـ File System Access API | سيُستخدم تلقائياً منتقي الملفات أو التنزيل |
| خطأ صلاحيات | الدور يفتقد `settings.edit` | تأكد من صلاحية المستخدم أو دوره |
| تعذر المزامنة | مفاتيح خاطئة أو RLS | راجع الإعدادات و`npm run cloud:check` |
| نسخة أكبر من 30MB مرفوضة | حجم الملف كبير | نظّف البيانات أو استخدم نسخة أصغر |
| لا يظهر تحديث فوري | لا يوجد Realtime | النظام يسحب عند العودة للتبويب (سلوك مقصود) |

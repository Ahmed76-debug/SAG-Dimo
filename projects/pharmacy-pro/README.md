# PharmaPro — منصة إدارة الصيدلية الذكية

نظام ويب متكامل لإدارة الصيدليات بواجهة عربية (RTL) وتصميم عصري متجاوب، يعمل **بدون أي حزم خارجية أو خطوة بناء**. يعتمد على Node.js المدمج وSQLite المدمجة في Node، ما يجعله سريعاً وسهل النشر على جهاز واحد أو شبكة صيدلية محلية.

## المزايا

### نقطة البيع (POS)
- بحث فوري بالاسم أو الكود أو الباركود، وتعامل كامل مع قارئ الباركود (Keyboard Wedge).
- سلة بيع سريعة، تعديل الكميات، خصم على الصنف أو على الفاتورة.
- تعليق الفواتير واسترجاعها، وعملاء نقدي/آجل، واختيار عميل أو إنشاء عميل جديد أثناء البيع.
- طرق دفع: نقدي، بطاقة، محفظة إلكترونية، آجل.
- حساب الباقي تلقائياً، ومنع البيع قبل فتح وردية.
- إيصال حراري 80mm وفاتورة A4 قابلة للطباعة.

### المخزون والمشتريات
- أصناف كاملة البيانات: الاسم العربي/الإنجليزي، الباركود، الكود الداخلي، التصنيف، الشركة، الشكل الدوائي، التركيز، سعر البيع والتكلفة، الحد الأدنى، صلاحية الروشتة.
- دفعات (Batches) وتواريخ صلاحية، وصرف تلقائي بنظام **FEFO** (الأقرب انتهاءً أولاً).
- تعديلات مخزون (إضافة/صرف/تسوية) مع سبب وحركة مسجلة.
- تنبيهات المخزون المنخفض والدفعات قاربة الانتهاء.
- فواتير شراء كاملة مع الدفعات، الدفع الجزئي، سداد الموردين، ومرتجعات المشتريات.
- ملفات الموردين والأرصدة وكشوف الحساب.

### المبيعات والعملاء
- سجل فواتير مع فلاتر تاريخ، طباعة، إلغاء، ومرتجعات جزئية/كلية.
- إرجاع الكميات إلى نفس دفعات الصرف، وطرق رد المبلغ (نقدي/بنك/خصم من حساب العميل).
- ملفات العملاء، التأمين، نقاط الولاء، الأرصدة، وكشف حساب تفصيلي.
- الروشتات الطبية: إنشاء/تعديل، بيانات الطبيب والمريض، أصناف الروشتة، وحالة الصرف.

### الورديات
- فتح وردية بنقدية افتتاحية، متابعة المبيعات والمرتجعات والحركات النقدية.
- إغلاق الوردية مع حساب النقدية المتوقعة والفرق تلقائياً.
- تقرير وردية قابل للطباعة، وسجل ورديات الموظفين.

### المحاسبة
- نظام **قيد مزدوج** حقيقي، مع ترحيل تلقائي للمبيعات والمشتريات والمرتجعات والمصروفات وتسويات المخزون.
- دليل حسابات، دفتر يومية، قيود يدوية متوازنة، دفتر أستاذ، ميزان مراجعة.
- قائمة أرباح وخسائر، ميزانية عمومية، تقرير ضريبة القيمة المضافة، وتقارير الموردين والعملاء.
- إدارة المصروفات وربطها بالحسابات المحاسبية.

### الإدارة والنظام
- مستخدمون وأدوار وصلاحيات دقيقة (22 صلاحية).
- إعدادات الصيدلية، العملة، الضريبة، الفاتورة، التنبيهات، والمظهر.
- نسخ احتياطي يدوي/تلقائي، واستعادة آمنة مع نسخة أمان قبل الاستعادة.
- سجل نشاط (Audit Log) لكل العمليات الحساسة.
- وضع داكن/فاتح، تصميم متجاوب للكمبيوتر والتابلت والهاتف.
- بحث شامل، إشعارات، ولوحة تحكم بمؤشرات ورسوم بيانية.

## المتطلبات

- **Node.js 22.5 أو أحدث** (مُختبر على Node.js 24.16). سبب الإصدار هو وحدة `node:sqlite` المدمجة.
- متصفح حديث: Chrome / Edge / Firefox / Safari.
- لا حاجة إلى `npm install` أو اتصال بالإنترنت.

> على Windows يمكن تثبيت Node.js من الموقع الرسمي: <https://nodejs.org>

## التشغيل السريع

### الطريقة الأولى — Windows
انقر نقراً مزدوجاً على:

```text
start.bat
```

سيفتح الخادم ويفتح المتصفح تلقائياً على <http://127.0.0.1:4173>.

### الطريقة الثانية — سطر الأوامر (كل الأنظمة)
من داخل مجلد المشروع:

```bash
node server/app.js
```

ثم افتح المتصفح على:

```text
http://127.0.0.1:4173
```

### تغيير المنفذ

```bash
node server/app.js --port=4174
```

أو:

```bash
# Windows PowerShell
$env:PORT=4174; node server/app.js

# macOS / Linux
PORT=4174 node server/app.js
```

### الوصول من أجهزة أخرى في الشبكة

الخادم يستمع افتراضياً على `127.0.0.1` فقط. للسماح بالوصول من أجهزة الشبكة:

```powershell
# Windows PowerShell
$env:HOST='0.0.0.0'; node server/app.js
```

```bash
# macOS / Linux
HOST=0.0.0.0 node server/app.js
```

ثم افتح من الجهاز الآخر:

```text
http://<IP-الجهاز-الذي-يشغل-الخادم>:4173
```

> يُنصح باستخدام شبكة موثوقة فقط، أو وضع الخادم خلف Reverse Proxy مع HTTPS عند التعرض للإنترنت.

## حسابات الدخول التجريبية

| الحساب | كلمة المرور | الدور | نطاق الوصول |
|---|---|---|---|
| `admin` | `admin123` | مدير النظام | كل الصلاحيات |
| `manager` | `manager123` | مدير الصيدلية | التشغيل، المخزون، المبيعات، التقارير، الورديات |
| `pharmacist` | `pharma123` | صيدلي | البيع، المخزون، المشتريات، الروشتات، المرتجعات |
| `cashier` | `cashier123` | كاشير | نقطة البيع، العملاء، الورديات |
| `accountant` | `acc123` | محاسب | المحاسبة، التقارير، المشتريات، العملاء |

> **مهم:** غيّر كلمات المرور الافتراضية فور بدء الاستخدام الفعلي من شاشة **المستخدمون والصلاحيات**.

## الملفات والبيانات

| المسار | الوصف |
|---|---|
| `data/pharmacy.db` | قاعدة بيانات SQLite الرئيسية |
| `data/pharmacy.db-wal` / `-shm` | ملفات WAL المؤقتة (تُدار تلقائياً) |
| `data/backups/` | مجلد النسخ الاحتياطي الافتراضي |
| `server/` | الخادم وواجهات API وقاعدة البيانات |
| `public/` | الواجهة الأمامية (HTML/CSS/JS) |

قاعدة البيانات تُنشأ تلقائياً عند أول تشغيل، وتُضاف بيانات تجريبية واقعية إذا كان جدول المستخدمين فارغاً فقط.

## النسخ الاحتياطي والاستعادة

من القائمة: **النسخ الاحتياطي**.

- يمكن اختيار أي مجلد للحفظ، بما في ذلك قرص خارجي أو مجلد شبكي.
- زر **اختيار مجلد** يفتح نافذة اختيار مجلد ويندوز الأصلية.
- زر **استعراض** يتيح التنقل بين المجلدات من داخل النظام.
- زر **إنشاء نسخة الآن** ينشئ ملف `.db` باستخدام `VACUUM INTO` (نسخة متسقة أثناء العمل).
- عند الاستعادة تُنشأ **نسخة أمان تلقائية** أولاً، ثم تُستبدل البيانات.
- جلسات الدخول الحالية تبقى صالحة بعد الاستعادة (يُحتفظ بالسر التشفيري).
- يمكن حذف النسخ القديمة من نفس الشاشة.

> يُنصح بنسخة احتياطية يومية على قرص مختلف عن قرص النظام.

## المستخدمون والصلاحيات

من القائمة: **المستخدمون والصلاحيات**.

- إنشاء وتعديل المستخدمين، تعطيل الحساب، وإعادة تعيين كلمة المرور.
- إنشاء أدوار مخصصة وتحديد صلاحياتها من 22 صلاحية موزعة على مجموعات.
- يمكن **تجاوز صلاحيات الدور** لمستخدم محدد واختيار صلاحيات مخصصة له (مثلاً كاشير بصلاحية نقطة بيع فقط).
- الأدوار النظامية محمية من الحذف، ودور مدير النظام يملك كل الصلاحيات دائماً.
- الصلاحيات تُفرض على الخادم وليس في الواجهة فقط.

أمثلة على الصلاحيات: `pos.use`، `products.manage`، `inventory.manage`، `purchases.manage`، `sales.manage`، `returns.manage`، `accounting.manage`، `users.manage`، `backup.manage`، `audit.view`.

## نقطة البيع والباركود

- امسح الباركود في حقل البحث ثم اضغط **Enter** لإضافة الصنف مباشرة.
- يمكن البحث بالاسم أو الكود أو الباركود، والتصفية بالتصنيف.
- اختصارات لوحة المفاتيح: `F2` بحث، `Enter` باركود، `F4` دفع، `F9` تعليق الفاتورة.
- طباعة ملصقات باركود Code 39 من شاشة تفاصيل الصنف.
- يجب فتح وردية قبل إتمام أي بيع.

## المحاسبة والتقارير

- كل عملية بيع/شراء/مرتجع/مصروف/تسوية مخزون تُرحَّل تلقائياً إلى دفتر اليومية.
- قائمة الأرباح والخسائر والميزانية العمومية تُحسب من القيود الفعلية.
- تقارير المبيعات تشمل الإجمالي، المرتجعات، الضريبة، التكلفة، الربح، طرق الدفع، أداء الموظفين، وأفضل الأصناف.
- يمكن تصدير الجداول إلى **Excel (.xls)** و**PDF** (عبر نافذة الطباعة) وطباعة التقارير بصيغة A4.

## الإعدادات المتقدمة

من شاشة **الإعدادات**:

- بيانات الصيدلية التي تظهر على الفواتير والتقارير.
- العملة، نسبة ضريبة القيمة المضافة، بداية السنة المالية.
- نص أسفل الفاتورة، الطابعة الافتراضية (إيصال حراري / A4)، إظهار الشعار.
- حد تنبيه المخزون، وأيام التنبيه قبل انتهاء الصلاحية.
- المظهر الافتراضي (فاتح/داكن/حسب الجهاز).

يمكن أيضاً تغيير المنفذ عبر `PORT` أو `--port=`، والاستماع عبر `HOST`.

## الأمان

- كلمات المرور تُخزَّن باستخدام **scrypt** مع Salt عشوائي، ولا تُخزَّن نصاً صريحاً.
- جلسات الدخول عبر رموز موقعة HMAC مع مدة صلاحية.
- كل مسار API محمي بصلاحية محددة، ويُتحقق من الصلاحية على الخادم.
- الخادم يستمع افتراضياً على `127.0.0.1` فقط.
- سجل النشاط يسجل العمليات الحساسة مع المستخدم والوقت وعنوان IP.
- عند الفتح على شبكة، استخدم كلمات مرور قوية وقيّد الوصول بجدار حماية.
- عند التعرض للإنترنت، ضع النظام خلف Reverse Proxy (Nginx/Caddy) مع HTTPS.

## حل المشكلات

### «المنفذ 4173 مستخدم بالفعل»
شغّل على منفذ آخر:

```bash
node server/app.js --port=4174
```

أو أغلق العملية القديمة. على Windows:

```powershell
Get-NetTCPConnection -LocalPort 4173 | Select-Object OwningProcess
Stop-Process -Id <PID> -Force
```

### `node` غير معروف
ثبّت Node.js 22.5+ وأعد فتح سطر الأوامر.

### `npm` محظور بسبب Execution Policy على Windows
المشروع لا يحتاج npm إطلاقاً. شغّله مباشرة عبر `node server/app.js` أو `start.bat`.

### صفحة بيضاء أو خطأ في الواجهة
- افتح أدوات المطور (F12) وتحقق من Console.
- تأكد من تحديث الصفحة بعد تعديل ملفات الواجهة.
- راجع سجل الخادم في نافذة الطرفية.

### بيانات تجريبية غير مرغوبة
البيانات التجريبية تُضاف فقط إذا كانت قاعدة البيانات جديدة. للبدء بقاعدة فارغة:
1. أنشئ نسخة احتياطية أولاً.
2. أوقف الخادم.
3. انقل `data/pharmacy.db` وملفات `-wal`/`-shm` إلى مجلد آخر.
4. أعد تشغيل الخادم — ستُنشأ قاعدة جديدة مع البيانات التجريبية.

### استعادة نسخة احتياطية
من شاشة **النسخ الاحتياطي** اختر الملف ثم اضغط **استعادة**. النظام ينشئ نسخة أمان تلقائية قبل الاستبدال.

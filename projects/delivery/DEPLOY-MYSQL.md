# طلباتك — التشغيل محليًا وعلى الاستضافة (SQLite / MySQL)

> الهدف: نفس الكود يعمل محليًا الآن، ويعمل على أي استضافة تدعم Node.js + MySQL
> بمجرد تغيير متغيّر واحد: `DATABASE_URL`.

---

## 1) الخلاصة السريعة

| البيئة | قاعدة البيانات | ما تحتاجه |
|---|---|---|
| جهازك الآن | SQLite (مدمجة في Node) | `node server.js` فقط |
| استضافة MySQL/MariaDB | MySQL 5.7+ / MariaDB 10.2+ | `DATABASE_URL` + `npm install` |
| PostgreSQL | غير مدعوم في طلباتك حاليًا | استخدم MySQL أو SQLite |

- لا حاجة لتعديل أي كود عند الانتقال من SQLite إلى MySQL.
- التطبيق ينشئ الجداول ويزرع البيانات الافتراضية **تلقائيًا** عند أول تشغيل لقاعدة فارغة.
- كل بياناتك (الطلبات، العملاء، الحسابات، المخزون…) تنتقل معك؛ لا شيء مربوط بالجهاز.

---

## 2) التجربة محليًا الآن (SQLite — بدون تثبيت أي شيء)

```powershell
cd delivery
node server.js
```

- الموقع: `http://localhost:8080/`
- لوحة الإدارة: `http://localhost:8080/admin`
- الدخول الافتراضي: `admin` / `admin123`

البيانات تُحفظ في `delivery/data/app.db`، والنسخ الاحتياطية في `delivery/data/backups/`.

لتجربة قاعدة نظيفة:

```powershell
$env:TALABATAK_DATA="C:\path\to\delivery-fresh"
node server.js
```

---

## 3) التجربة محليًا على MySQL/MariaDB (اختياري لكنه مستحسن قبل الرفع)

### أ) أنشئ قاعدة بيانات فارغة

من phpMyAdmin أو سطر الأوامر:

```sql
CREATE DATABASE talabatak CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

### ب) أنشئ ملف `.env`

انسخ `.env.example` إلى `.env` وعدّله:

```env
DATABASE_URL=mysql://USER:PASSWORD@HOST:3306/talabatak
PORT=8080
HOST=0.0.0.0
TALABATAK_DATA=./data
```

> إذا كانت كلمة المرور تحتوي `@` أو `#` أو `/` أو `:` فاستخدم ترميز URL:
> `@` → `%40`، `#` → `%23`، `/` → `%2F`، `:` → `%3A`.

### ج) ثبّت الحزم ثم شغّل

```powershell
npm install --omit=dev
npm start
```

- عند أول تشغيل: يُنشئ الجداول من `schema/001_init.sql`، ثم يزرع `seed.json` تلقائيًا.
- عند إعادة التشغيل: لا يعيد الزرع (يتحقق من وجود صف الشركة).

### د) بديل: إنشاء الجداول يدويًا

```powershell
# طباعة SQL لاستيراده في phpMyAdmin
node scripts/schema-mysql.js --print > schema.sql

# أو تنفيذه مباشرة باستخدام DATABASE_URL
node scripts/schema-mysql.js
```

ثم شغّل التطبيق؛ سيكمل الزرع إذا كانت القاعدة فارغة.

## 4) خطوات الرفع على أي استضافة (Node.js + MySQL)

1. **أنشئ قاعدة MySQL** من لوحة الاستضافة (cPanel / phpMyAdmin / لوحة alwaysdata).
   - احتفظ بـ: `Host`، `Port` (غالبًا 3306)، `Database`، `User`، `Password`.
   - تأكد أن قاعدة البيانات `utf8mb4`.
2. **ارفع ملفات المشروع** عبر Git أو FTP/مدير الملفات:
   - ارفع: `server.js`، `lib/`، `public/`، `schema/`، `scripts/`، `package.json`، `package-lock.json`، `seed.json`.
   - **لا ترفع**: `node_modules/`، `data/`، `.env`، `*.db`، `backups/`.
3. **ثبّت الحزم على الخادم** (من Terminal/SSH أو أمر النشر في اللوحة):

   ```bash
   npm install --omit=dev
   ```

4. **أنشئ `.env` على الخادم**:

   ```env
   DATABASE_URL=mysql://USER:PASSWORD@HOST:3306/DATABASE
   HOST=0.0.0.0
   TALABATAK_DATA=/home/USER/talabatak-data
   ```

   - `TALABATAK_DATA` يجب أن يكون **قابلًا للكتابة ودائمًا** (خارج مجلد الكود إن أمكن) لتُحفظ النسخ الاحتياطية.
   - لا تضع `PORT` إلا إذا طلبته الاستضافة؛ معظمها يضبطه تلقائيًا. الكود يقرأ `process.env.PORT` ويستمع على `0.0.0.0`.

5. **أمر التشغيل**: `npm start` أو `node server.js`.
6. **أول تشغيل**: راقب السجل؛ يجب أن ترى `✓ تم زرع بيانات طلباتك في MySQL` ثم عنوان الموقع.
7. **غيّر كلمة مرور المدير فورًا** من: لوحة الإدارة → المستخدمون → المدير العام.

> إذا كانت الاستضافة توفّر Node.js لكن لا توفّر MySQL مجانًا، يمكنك استخدام
> قاعدة MySQL خارجية مجانية (مثل `db4free.net` أو `freesqldatabase.com`)
> ووضع بياناتها في `DATABASE_URL`. راجع حدود المساحة والاتصالات قبل الاعتماد عليها.

## 5) استضافات مجانية (بدون بطاقة ائتمان)

| الاستضافة | Node.js | MySQL مجاني | ملاحظات |
|---|---|---|---|
| **alwaysdata** | نعم | نعم (خطة مجانية) | الأفضل لهذا المشروع: Node + MySQL في مكان واحد. قد تحتاج تفعيل الموقع من اللوحة. |
| **Koyeb / Render (خطة مجانية)** | نعم | لا (استخدم MySQL خارجية) | التطبيق ينام عند عدم الاستخدام في بعض الخطط؛ مناسب للتجربة. |
| **db4free.net** | — | MySQL مجاني | قاعدة خارجية فقط، بلا ضمانات، وقد تُحذف عند عدم النشاط. |
| **freesqldatabase.com** | — | MySQL مجاني صغير | مساحة صغيرة (غالبًا 5MB) — لا تكفي لصور المنتجات الكثيرة. |
| **InfinityFree** | **لا** | MySQL فقط | لا يشغّل Node.js إطلاقًا؛ لا ترفع عليه هذا المشروع. |
| **Vercel / Netlify** | Serverless | لا | غير مناسبين لخادم Node دائم + نظام ملفات للنسخ الاحتياطية. |
| **VPS مدفوع** | نعم | تثبّته بنفسك | الأفضل للإنتاج، لكنه ليس مجانيًا. |

**التوصية:** ابدأ بـ **alwaysdata** (Node + MySQL مجانًا). للتجربة السريعة يمكنك
تشغيل الموقع على Koyeb/Render مع MySQL من `db4free.net`. للإنتاج الفعلي استخدم
VPS أو استضافة Node مدفوعة، مع نسخ احتياطي دوري.

## 6) النسخ الاحتياطي والاسترجاع

من لوحة الإدارة → النظام → النسخ الاحتياطي:

- **SQLite**: ملفات `.db` (تُنشأ بـ `VACUUM INTO` — آمنة أثناء التشغيل).
- **MySQL**: ملفات `.json` (تصدير كل الجداول).
- يمكنك تغيير مجلد النسخ أو إضافة مجلدات من نفس الشاشة.
- زر **استرجاع** يأخذ نسخة أمان تلقائية قبل الاسترجاع.
- للتنزيل: زر التنزيل بجانب النسخة.

> بعد الاسترجاع على MySQL تُعاد كل الجداول من ملف JSON، عدا `sessions`
> و`backup_dirs` (تبقى جلساتك ومجلدات النسخ الحالية كما هي).

## 7) ملاحظات تقنية مهمة

### الجسر المتزامن (Sync Bridge)

طلباتك مكتوب بأسلوب SQLite المتزامن (`all/one/run`). لدعم MySQL دون إعادة كتابة
٢٥٩ موضعًا، أضفنا `lib/mysql-sync.js` + `lib/mysql-sync-worker.js`:

- الاستعلام يُنفَّذ في **Worker Thread** على اتصال MySQL واحد.
- الخيط الرئيسي ينتظر النتيجة عبر `SharedArrayBuffer` + `Atomics.wait`.
- النتيجة: نفس واجهة `all/one/run` القديمة، و`lib/api.js` شبه دون تغيير.

**المقايضة:** كل استعلام يحجب الخيط الرئيسي مؤقتًا (event loop). هذا مقبول
لتطبيق صغير/داخلي كما هو الآن، لكنه ليس مناسبًا لآلاف الطلبات المتزامنة.
إذا كبر المشروع، الحل التدريجي هو تحويل `lib/db.js` و`lib/api.js` إلى `async/await`
(كما في مشروعي `forensic-accountant` و`smart-profile-cms`).

### توافق SQL

- استُبدل `notifications.read` بـ `is_read` لأن `read` كلمة محجوزة في MySQL.
  الواجهة لا تتأثر: الخادم يُرجع `is_read AS \`read\``.
- استُبدلت دوال التواريخ الخاصة بـ SQLite مثل `date('now',...)` بـ `SUBSTR(created_at,1,10)`
  لتعمل على المحركين.
- `nextCode` يستخدم `CAST(... AS SIGNED)` و`ON DUPLICATE KEY UPDATE` على MySQL.
- الجداول كلها `InnoDB` و`utf8mb4_unicode_ci`؛ الصور والنصوص الطويلة `LONGTEXT`/`TEXT`.
- السكربت لا يستخدم مفاتيح أجنبية (Foreign Keys) حاليًا؛ لذلك الاستيراد والاسترجاع بسيطان.

### الملفات المهمة

| الملف | وظيفته |
|---|---|
| `lib/db.js` | طبقة قاعدة البيانات + الترحيلات + الزرع |
| `lib/mysql-sync.js` | جسر MySQL المتزامن (الخيط الرئيسي) |
| `lib/mysql-sync-worker.js` | تنفيذ الاستعلامات في Worker |
| `schema/001_init.sql` | مخطط MySQL الكامل (34 جدولًا) |
| `seed.json` | بيانات البداية (شركة، عملاء، منتجات، حسابات…) |
| `scripts/schema-mysql.js` | طباعة/تنفيذ مخطط MySQL |
| `.env.example` | نموذج الإعدادات |

## 8) قائمة أمان قبل النشر

- [ ] غيّر كلمة مرور `admin` (الافتراضية `admin123`) فورًا.
- [ ] استخدم HTTPS (شهادة SSL من الاستضافة).
- [ ] لا ترفع `.env` إلى Git، ولا تشارك `DATABASE_URL`.
- [ ] اجعل `TALABATAK_DATA` خارج مجلد الموقع إن أمكن، وصلاحياته 700.
- [ ] فعّل نسخًا احتياطيًا دوريًا (يوميًا) واحتفظ بنسخة خارج الخادم.
- [ ] راجع صلاحيات المستخدمين من شاشة المستخدمين (لا تعطِ admin لغير المدير).
- [ ] احذف `data-test` و`data-mysql` و`data-seed` من حزمة النشر (ليست مطلوبة).

## 9) استكشاف الأخطاء

| الخطأ | السبب المحتمل | الحل |
|---|---|---|
| `Access denied for user` | بيانات `DATABASE_URL` خاطئة أو المستخدم لا يملك صلاحية من المضيف | راجع المستخدم/كلمة المرور، واستخدم `%` في Host بالمستضيف أو أضف IP الخادم |
| `ECONNREFUSED` / timeout | المضيف/المنفذ خطأ أو الاتصال الخارجي محظور | جرّب `127.0.0.1` إن كانت القاعدة على نفس الخادم، وتأكد من فتح المنفذ |
| `ER_NO_SUCH_TABLE` | لم يُستورد المخطط ولم يُشغّل التطبيق بعد | `node scripts/schema-mysql.js` أو استورد `schema/001_init.sql` ثم أعد التشغيل |
| `Incorrect ... value` عند الزرع | بيانات `seed.json` قديمة/غير متوافقة | استخدم `seed.json` المرفق بعد إصلاحه، أو احذف الجداول وأعد التشغيل |
| `Too many connections` | حدّ الاستضافة منخفض | أغلق عمليات Node القديمة؛ التطبيق يستخدم اتصالًا واحدًا |
| نصوص عربية مشوّهة | ترميز الاتصال ليس utf8mb4 | تأكد من `CHARACTER SET utf8mb4` ومن `?charset=utf8mb4` (مضبوط تلقائيًا) |
| `Data too long for column` | قيمة أطول من عرض العمود | راجع الحقل/البيانات؛ معظم الحقول النصية الطويلة `TEXT` بالفعل |
| لا يظهر عنوان الموقع | الاستضافة تتوقع `PORT` مختلفًا | لا تثبّت `PORT` يدويًا إلا إذا طلبته اللوحة؛ الكود يقرأه من البيئة |

## 10) بيانات الدخول الافتراضية

- اسم المستخدم: `admin`
- كلمة المرور: `admin123`

**غيّرها قبل أي نشر عام.** التطبيق يطبعها في سجل التشغيل للتذكير فقط.

إذا نسيت كلمة المرور على MySQL، شغّل التطبيق مرة واحدة (حتى يجهّز القاعدة)
ثم نفّذ `RESET-ADMIN-MYSQL.sql` من phpMyAdmin؛ ستصبح
`admin` / `admin123`، ثم غيّرها فور الدخول.

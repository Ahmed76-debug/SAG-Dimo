# مفتاح · Miftah Studio

استوديو تراخيص سطح مكتب احترافي، عربي بالكامل واتجاه RTL، لإدارة المنتجات والعملاء والتراخيص والتفعيلات — مع توليد مفاتيح موقّعة رقمياً، وتفعيل أونلاين وأوفلاين، ونظام مستخدمين وأدوار، ونسخ احتياطي/استعادة، وستّ سمات بصرية.

> **الإصدار:** 2.0.0 — يتطلب Node.js **22.13 أو أحدث** (يستخدم `node:sqlite` المدمج).

## التشغيل السريع

```powershell
cd miftah-studio
npm.cmd install
npm.cmd run dev
```

- الواجهة: <http://127.0.0.1:5173>
- الـ API: <http://127.0.0.1:4781>

للبناء والتشغيل الإنتاجي (خادم واحد يقدّم الواجهة والـ API معاً):

```powershell
npm.cmd run build
npm.cmd start
# افتح http://127.0.0.1:4781
```

> على Windows استخدم `npm.cmd` وليس `npm` إذا كانت سياسة PowerShell تمنع `npm.ps1`.
> عند أول تشغيل تُنشأ قاعدة البيانات وتُزرع بيانات عرض تجريبية تلقائياً. لإعادة التهيئة لاحقاً أوقف الخادم ثم: `Remove-Item data\miftah.db* -Force`.

## تشغيل سطح المكتب على Windows

المشروع يعمل كتطبيق سطح مكتب محلي عبر خادم Node وواجهة المتصفح في وضع التطبيق:

```powershell
.\launch.cmd
```

يقوم `launch.ps1` تلقائياً بـ:

1. التأكد من وجود بناء إنتاجي (`dist`) — ويبنيه عند الحاجة.
2. تشغيل الخادم في الخلفية إذا لم يكن يعمل، مع سجل في `data\server.log`.
3. انتظار جاهزية `/api/v1/health`.
4. فتح نافذة Edge بوضع التطبيق (`--app`) على المنفذ `4781`، أو المتصفح الافتراضي إن لم يوجد Edge.

يمكنك إنشاء اختصار على سطح المكتب يشير إلى `launch.cmd` واختيار أيقونة المشروع. لإيقاف الخادم أغلق نافذة الطرفية/العملية `node` أو استخدم:

```powershell
Get-Process node | Stop-Process
```

> لتغليف التطبيق كملف تنفيذي مستقل لاحقاً، البنية جاهزة للانتقال إلى Electron/Tauri: الخادم مستقل في `server/` والواجهة تُبنى في `dist/`، ويمكن للعملية الرئيسية تشغيل الخادم وفتح نافذة على `http://127.0.0.1:4781`.

## المعمارية

```
┌─────────────────────────────┐     /api (JWT)      ┌──────────────────────────────┐
│  React 19 + Vite 7 (RTL)    │ ──────────────────► │  Express 5 API (Node.js)     │
│  Tailwind v4 + framer-motion│ ◄────────────────── │  node:sqlite (WAL)           │
│  6 themes + density         │    /api/v1 (API key)│  Ed25519 + AES-256-GCM       │
└─────────────────────────────┘                     └──────────────────────────────┘
                                                              │
                                          data/miftah.db ◄────┤
                                          keys/*.pem     ◄────┤
                                          backups/*.mftbak ◄──┘
```

- **الواجهة:** Vite + React 19 + TypeScript + Tailwind CSS v4، رسوم بيانية SVG مخصصة، أيقونات Lucide، حركات Framer Motion، خط IBM Plex Sans Arabic محلي.
- **الخادم:** Express 5، جلسات موقّعة HS256 (متوافقة مع JWT)، كلمات مرور scrypt، تحكم صلاحيات على مستوى كل مسار.
- **قاعدة البيانات:** SQLite مدمج عبر `node:sqlite` مع WAL؛ الجداول: `roles`, `users`, `products`, `customers`, `licenses`, `activations`, `activation_requests`, `audit_logs`, `settings`, `api_keys`, `backups`.
- **التشفير:**
  - مفاتيح التراخيص تُخزَّن كبصمة SHA-256 للبحث + نسخة مشفّرة AES-256-GCM للكشف عند الحاجة.
  - المستندات الموقّعة (ترخيص أوفلاين/توكن تفعيل) تُوقَّع بـ **Ed25519**، والمفتاح العام متاح عبر `/api/v1/public-key`.
  - سرّ الخادم (`data/.secret`) يُولَّد تلقائياً ويُستخدم لتوقيع الجلسات وتشفير المفاتيح.

## نماذج التراخيص والتفعيل

### الخطط

| الخطة | الوصف |
| --- | --- |
| `perpetual` دائم | بلا تاريخ انتهاء — دفعة واحدة |
| `subscription` اشتراك | صلاحية حتى تاريخ محدد، قابلة للتجديد |
| `trial` تجريبي | فترة قصيرة الأمد (أيام محددة) |

### أنماط التفعيل

| النمط | السلوك |
| --- | --- |
| `online` أونلاين | التطبيق يستدعي `/api/v1/activate` ويحصل على توكن موقّع، ثم يتحقق دورياً بـ `/validate` |
| `offline` أوفلاين | يُصدر الاستوديو مستند ترخيص موقّعاً يُحمل يدوياً إلى جهاز العميل |
| `hybrid` هجين | يدعم المسارين معاً حسب اتصال الجهاز |

### دورة حياة الترخيص

`active` نشط → `expired` منتهٍ (تلقائياً حسب التاريخ) / `suspended` موقوف / `revoked` ملغى.
كل عملية تُسجَّل في سجل النشاط، وكل تفعيل يحجز مقعداً حتى إلغاء التفعيل.

## واجهة API

### مصادقة الواجهة (لوحة التحكم)

```http
POST /api/auth/login
Content-Type: application/json

{ "username": "admin", "password": "admin123" }
```

تُعيد `{ ok: true, data: { token, user } }`. أرسل التوكن لاحقاً:

```http
Authorization: Bearer <token>
```

### واجهة التفعيل العامة (لتطبيقات العملاء)

كل الطلبات تحت `/api/v1` وتتطلب ترويسة `X-API-Key` (عدا `health` و`branding` و`public-key`).

```bash
# فحص الصحة
curl http://127.0.0.1:4781/api/v1/health

# تفعيل جهاز
curl -X POST http://127.0.0.1:4781/api/v1/activate \
  -H "Content-Type: application/json" \
  -H "X-API-Key: mft_live_demo_..." \
  -d '{"licenseKey":"MFT-XXXX-XXXX-XXXX-XXXX","machineId":"PC-001","machineName":"Workstation","os":"Windows 11"}'

# تحقق دوري (نبضة)
curl -X POST http://127.0.0.1:4781/api/v1/validate \
  -H "Content-Type: application/json" \
  -H "X-API-Key: mft_live_demo_..." \
  -d '{"licenseKey":"MFT-XXXX-XXXX-XXXX-XXXX","machineId":"PC-001"}'

# إلغاء تفعيل
curl -X POST http://127.0.0.1:4781/api/v1/deactivate \
  -H "Content-Type: application/json" \
  -H "X-API-Key: mft_live_demo_..." \
  -d '{"licenseKey":"MFT-XXXX-XXXX-XXXX-XXXX","machineId":"PC-001"}'

# طلب تفعيل أوفلاين ثم متابعة الطلب
curl -X POST http://127.0.0.1:4781/api/v1/offline-request \
  -H "Content-Type: application/json" \
  -H "X-API-Key: mft_live_demo_..." \
  -d '{"licenseKey":"MFT-XXXX-XXXX-XXXX-XXXX","machineId":"PC-002","machineName":"Offline PC"}'

curl -H "X-API-Key: mft_live_demo_..." \
  http://127.0.0.1:4781/api/v1/offline-request/REQ-XXXXXX

# المفتاح العام للتحقق من التوقيعات
curl http://127.0.0.1:4781/api/v1/public-key
```

الاستجابات موحّدة الشكل:

```json
{ "ok": true, "data": { } }
{ "ok": false, "error": { "code": "invalid_license_key", "message": "..." } }
```

مفاتيح API تُدار من **الإعدادات ← مفتاح API** داخل الاستوديو (إنشاء/إلغاء، مع نطاقات `activate`/`validate`).

## النسخ الاحتياطي والاستعادة

- **المكان:** من صفحة النسخ الاحتياطي اختر أي مجلد (متصفح مجلدات داخلي، أو نافذة Windows الأصلية على الجهاز المحلي).
- **الصيغة:** ملف `.mftbak` = JSON مضغوط gzip يحتوي قاعدة SQLite بترميز Base64 + بصمة SHA-256 + بيانات الإصدار والتاريخ. عند الاستعادة يُتحقق من البصمة أولاً.
- **الاستعادة:** تنشئ تلقائياً نسخة `pre-restore` قبل استبدال قاعدة البيانات، ثم تعيد فتح الاتصال.
- **التلقائي:** نسخة تلقائية كل عدد ساعات محدد من الإعدادات، مع الاحتفاظ بآخر N نسخة (يُنظَّف الأقدم تلقائياً).
- **الرفع/التنزيل:** يمكن تنزيل النسخ أو استعادة نسخة مرفوعة من جهاز آخر عبر الواجهة.
- **تنبيه مهم:** ملف `.mftbak` يحوي قاعدة البيانات فقط. **لا يضم** `data/.secret` ولا مجلد `keys/`. احتفظ بنسخة منهما بشكل منفصل، وإلا فقدت القدرة على فك تشفير المفاتيح القديمة أو التحقق من التوكنات/التوقيعات السابقة بعد الاستعادة على جهاز آخر.

الإعدادات الافتراضية: كل 24 ساعة، الاحتفاظ بـ 20 نسخة تلقائية، مجلد `backups/` داخل المشروع.

## النشر لعدة أجهزة (خادم العميل)

لتشغيل الاستوديو على جهاز واحد في شبكة العميل واستخدامه من عدة حواسيب:

```powershell
# على جهاز الخادم
$env:HOST = "0.0.0.0"
$env:PORT = "4781"
npm.cmd start
```

- افتح المنفذ في جدار الحماية (PowerShell كمسؤول):

```powershell
New-NetFirewallRule -DisplayName "Miftah Studio" -Direction Inbound -Protocol TCP -LocalPort 4781 -Action Allow
```

- من بقية الأجهزة: `http://<IP-الخادم>:4781`.
- تأكد أن الخادم والواجهة يعملان (البناء الإنتاجي يخدم `dist` تلقائياً).
- **للإنتاجية:** ضع reverse proxy مثل Caddy/Nginx مع شهادة TLS أمام المنفذ، ولا تعرّضه مباشرة للإنترنت. الواجهة العامة (`/api/v1`) تستخدم مفاتيح API، ولوحة التحكم تستخدم جلسات مستخدمين — كلاهما يجب أن يمر عبر HTTPS خارج الشبكة المحلية.
- النسخ الاحتياطي والاستعادة متاحان من أي جهاز عبر الواجهة، لكن اختيار مجلد محلي/نافذة Windows يعمل فقط عندما يكون الخادم على نفس جهاز المتصفح. في النشر الشبكي استخدم مساراً مشتركاً على الخادم أو نزّل/ارفع ملف `.mftbak`.

## الأوامر والسكربتات


## ملاحظات أمنية

1. **غيّر بيانات الدخول التجريبية** فوراً من صفحة الفريق، وأنشئ مفتاح API جديداً وألغِ التجريبي.
2. احتفظ بـ `data/.secret` و`keys/` في مكان آمن — فقدهما يعني فقدان فك تشفير المفاتيح والتحقق من التوقيعات السابقة.
3. ملفات `.mftbak` غير مشفّرة (مضغوطة فقط) وتحتوي بيانات العملاء والمفاتيح المشفّرة؛ خزّنها في مجلد محمي بصلاحيات مناسبة.
4. في النشر الشبكي استخدم HTTPS عبر reverse proxy، وقيّد الوصول للمنفذ 4781 على الشبكة المحلية/ VPN.
5. الصلاحيات مفروضة على الخادم في كل مسار وليست إخفاءً في الواجهة فقط.
6. سجلات الدخول محدودة المعدل (8 محاولات/10 دقائق لكل IP)، والواجهة العامة محدودة بـ 180 طلباً/دقيقة لكل IP.

## حل المشكلات

| المشكلة | الحل |
| --- | --- |
| `node:sqlite` غير موجود | استخدم Node.js 22.13+ (`node -v`) |
| `npm.ps1 cannot be loaded` | استخدم `npm.cmd` أو `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` |
| المنفذ 4781 مشغول | غيّر `$env:PORT` أو أوقف العملية: `Get-NetTCPConnection -LocalPort 4781` ثم `Stop-Process -Id <PID>` |
| الواجهة تفتح لكن API لا يستجيب | شغّل `npm.cmd run dev` (يشغّل API والواجهة معاً) أو `npm.cmd start` بعد البناء |
| نسيت كلمة المرور | أوقف الخادم واحتفظ بنسخة من `data/miftah.db*`، ثم أعد التهيئة التجريبية أو استعد نسخة سابقة |
| بعد الاستعادة فقدت فك تشفير المفاتيح | استعد أيضاً `data/.secret` و`keys/` من النسخة اليدوية |
| شاشة بيضاء بعد تحديث نسخة | امسح كاش المتصفح أو أعد `npm.cmd run build` وتأكد أن `dist/index.html` موجود |

# كافيه برو — التشغيل محليًا وعلى الاستضافة (SQLite / MySQL)

> نفس الكود يعمل محليًا بـ SQLite، وعلى أي استضافة تدعم Node.js + MySQL
> بمجرد تغيير `DATABASE_URL`.

---

## 1) الخلاصة

| البيئة | قاعدة البيانات | المتطلبات |
|---|---|---|
| جهازك | SQLite مدمجة (`node:sqlite`) | Node.js 22.13+ |
| الاستضافة | MySQL 5.7+ / MariaDB 10.2+ | Node.js 20+ + `npm install` |
| PostgreSQL | غير مدعوم في هذا الإصدار | استخدم MySQL أو SQLite |

- لا حاجة لتعديل الكود بين المحركين.
- التطبيق ينشئ الجداول والبيانات الافتراضية تلقائيًا عند أول تشغيل.
- لم يعد المشروع يستخدم `better-sqlite3` أو `pg`؛ لا مكتبات أصلية (native) على الاستضافة.

---

## 2) محليًا (SQLite)

```powershell
cd cafe-manager
npm install
npm start
```

- العنوان: `http://localhost:3000` (أو أول منفذ حر بعد 3000).
- الدخول الافتراضي: `admin` / `admin123`.
- قاعدة البيانات: `cafe.db` بجوار المشروع.
- لتجربة قاعدة نظيفة:

```powershell
$env:CAFE_DB="C:\path\to\cafe-test.db"
npm start
```

> SQLite المحلية تحتاج Node.js **22.13+** لأنها تستخدم `node:sqlite`.

---

## 3) MySQL محليًا (اختياري)

### أ) أنشئ قاعدة البيانات

```sql
CREATE DATABASE cafe CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

### ب) أنشئ `.env`

```env
DATABASE_URL=mysql://USER:PASSWORD@HOST:3306/cafe
PORT=3000
```

> إذا كانت كلمة المرور تحتوي `@` أو `#` أو `/` أو `:` استخدم ترميز URL:
> `@` → `%40`، `#` → `%23`، `/` → `%2F`، `:` → `%3A`.

### ج) شغّل

```powershell
npm install
npm start
```

سيُنشئ الجداول من `schema/001_init.sql` ويزرع الحسابات/الأصناف/الطاولات إذا كانت القاعدة فارغة.

بديل يدوي:

```powershell
npm run db:schema -- --print > schema.sql   # للاستيراد في phpMyAdmin
npm run db:schema                           # تنفيذ مباشر باستخدام DATABASE_URL
```

## 4) نقل بيانات SQLite الحالية إلى MySQL

السكربت يقرأ `cafe.db` (أو `CAFE_DB`) وينسخ كل الجداول إلى MySQL:

```powershell
# معاينة فقط (لا يكتب شيئًا)
$env:DATABASE_URL="mysql://USER:PASSWORD@HOST:3306/cafe"
npm run sync:mysql

# تنفيذ النقل (يفرّغ جداول MySQL المستهدفة أولًا!)
npm run sync:mysql -- --yes
```

> ⚠️ خُذ نسخة احتياطية من قاعدة MySQL المستهدفة قبل `--yes`.
> السكربت ينقل: الفروع، المستخدمين، الموردين، الحسابات، الأصناف، الوصفات،
> المبيعات، المشتريات، المالية، اليومية، الشيفتات، الطاولات، الطلبات وبنودها.
> بعد النقل شغّل التطبيق بنفس `DATABASE_URL` — الدخول يبقى بنفس مستخدمي
> قاعدة SQLite وكلمات مرورهم.

---

## 5) الرفع على الاستضافة

1. أنشئ قاعدة MySQL (cPanel / phpMyAdmin / لوحة alwaysdata) بترميز `utf8mb4`.
2. ارفع ملفات المشروع **بدون** `node_modules` و`cafe.db*` و`.env`:
   `server.js`، `db.js`، `public/`، `schema/`، `scripts/`، `package.json`، `package-lock.json`.
3. على الخادم:

   ```bash
   npm install --omit=dev
   ```

4. أنشئ `.env`:

   ```env
   DATABASE_URL=mysql://USER:PASSWORD@HOST:3306/DATABASE
   PORT=3000
   ```

   - معظم الاستضافات تضبط `PORT` تلقائيًا؛ الكود يقرأه ويستمع على `0.0.0.0`.
   - إن كانت القاعدة على نفس الخادم استخدم `127.0.0.1` بدل اسم النطاق.
   - إذا كانت الاستضافة تطلب SSL أضف `?ssl=true` إلى الرابط.

5. أمر التشغيل: `npm start` أو `node server.js`.
6. أول تشغيل: تُنشأ الجداول وتُزرع البيانات الافتراضية.
7. **غيّر كلمة مرور المدير فورًا** من: المستخدمون → تعديل.

> إذا كانت قاعدة MySQL قديمة/فارغة وتريد بياناتك الحالية: استخدم
> `npm run sync:mysql -- --yes` من جهازك مع `DATABASE_URL` الخاص بالاستضافة.

## 6) استضافات مجانية (بدون بطاقة)

| الاستضافة | Node.js | MySQL | ملاحظات |
|---|---|---|---|
| **alwaysdata** | نعم | نعم (مجاني) | الأفضل: Node + MySQL في مكان واحد. |
| **Koyeb / Render (مجاني)** | نعم | لا | استخدم MySQL خارجية مثل `db4free.net`. |
| **db4free.net** | — | MySQL مجاني | بلا ضمانات، قد تُحذف عند عدم النشاط. |
| **freesqldatabase.com** | — | MySQL صغير | مساحة 5MB غالبًا — قد لا تكفي. |
| **InfinityFree** | **لا** | MySQL فقط | لا يشغّل Node.js. |
| **Vercel / Netlify** | Serverless | لا | غير مناسب لخادم Node دائم. |

**التوصية:** alwaysdata للتجربة المجانية، أو VPS/استضافة Node مدفوعة للإنتاج.

## 7) النسخ الاحتياطي والاسترجاع

- من لوحة الإدارة → النسخ الاحتياطي: يُصدّر كل الجداول كـ JSON.
- الاسترجاع يفرّغ الجداول ثم يعيد إدخال الصفوف بنفس المعرّفات.
- بعد الاسترجاع على MySQL يُعاد ضبط `AUTO_INCREMENT` لكل جدول.
- على SQLite يُحدَّث `sqlite_sequence`.
- خُذ نسخة قبل أي استرجاع؛ الاسترجاع يستبدل البيانات الحالية.

## 8) ملاحظات تقنية

- `desc` كلمة محجوزة في MySQL؛ لذلك تُكتب بين backticks (`` `desc` ``) في كل
  استعلامات الإدراج/التحديث/الاسترجاع. واجهة API لا تتغير.
- `$1,$2...` تُحوَّل تلقائيًا إلى `?` مع تكرار القيم عند الحاجة؛ نفس الاستعلام
  يعمل على SQLite وMySQL.
- `ON CONFLICT` استُبدل بـ `INSERT IGNORE` (MySQL) و`INSERT OR IGNORE` (SQLite).
- `COUNT(*)::int` (PostgreSQL) أُزيل؛ `COUNT(*)` يعمل على المحركين.
- الأعمدة المالية `DOUBLE` لتعود أرقامًا في JavaScript (لا نصوص DECIMAL).
- الصور/النصوص الطويلة `TEXT`، والأسماء الفريدة `VARCHAR(191)` لتوافق فهارس
  utf8mb4 في MySQL 5.7.
- لا مفاتيح أجنبية (Foreign Keys) في المخطط الحالي؛ لذلك الاستيراد والاسترجاع بسيطان.
- الجلسات في الذاكرة (`Map`) وتنتهي عند إعادة تشغيل الخادم — هذا سلوك المشروع
  الأصلي، وليس تغييرًا.

## 9) استكشاف الأخطاء

| الخطأ | السبب | الحل |
|---|---|---|
| `Access denied` | بيانات `DATABASE_URL` أو صلاحية المضيف | راجع المستخدم/كلمة المرور وترميز URL، وأضف IP الخادم في cPanel |
| `ECONNREFUSED` | المضيف/المنفذ خطأ أو الاتصال الخارجي محظور | استخدم `127.0.0.1` إن كانت القاعدة محلية، وتأكد من المنفذ 3306 |
| `ER_NO_SUCH_TABLE` | لم يُستورد المخطط | `npm run db:schema` أو أعد تشغيل التطبيق |
| `Incorrect ... value` | بيانات قديمة/نوع غير متوافق | استخدم سكربت النقل من SQLite بدل الإدخال اليدوي |
| `Too many connections` | حدّ الاستضافة | أغلق عمليات Node القديمة؛ Pool محدود بـ 10 اتصالات |
| نصوص عربية مشوّهة | ترميز ليس utf8mb4 | أنشئ القاعدة بـ `utf8mb4` وتأكد من `charset=utf8mb4` |
| لا يفتح الموقع | الاستضافة تتوقع منفذًا مختلفًا | لا تثبّت `PORT` يدويًا إلا إذا طلبته اللوحة |
| `PostgreSQL غير مدعوم` | رابط `postgres://` | استخدم `mysql://` أو احذف `DATABASE_URL` لـ SQLite |

## 10) بيانات الدخول الافتراضية

- المستخدم: `admin`
- كلمة المرور: `admin123`

**غيّرها قبل النشر العام.** إذا كانت لديك قاعدة قديمة واستوردتها، فكلمة المرور
هي نفس كلمة مرور تلك القاعدة (وليس بالضرورة `admin123`).

إذا نسيت كلمة المرور على MySQL، نفّذ `RESET-ADMIN-MYSQL.sql` من phpMyAdmin؛
ستصبح `admin` / `admin123`، ثم غيّرها فور الدخول.
